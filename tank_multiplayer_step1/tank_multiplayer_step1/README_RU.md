# Танковый Deathmatch — сетевой этап 1

Этот пакет поднимает минимальный WebSocket relay и добавляет в проект Defold клиентский `network_manager.script`. На этом этапе мы проверяем подключение, уникальные ID игроков и обмен сетевыми событиями. Контроллеры танка и `bot_spawner` пока не изменяются; удалённые танки ещё не создаются автоматически.

## 1. Сервер Node.js

Требуется Node.js (рекомендуется актуальная LTS-версия).

В Windows открой PowerShell в папке `server` и выполни:

```powershell
npm install
npm start
```

Сервер слушает `0.0.0.0:8080`. Остановить его: `Ctrl+C`.

## 2. WebSocket extension для Defold

В `game.project` открой Dependencies и добавь:

```text
https://github.com/defold/extension-websocket/archive/refs/tags/4.2.4.zip
```

Сохрани `game.project`, дождись загрузки зависимости и выполни Project > Build.

Официальная документация: https://defold.com/extension-websocket/

## 3. Добавь network manager в коллекцию

1. Скопируй `defold/network_manager.script` в ресурсы проекта.
2. В активной игровой коллекции создай Game Object с id `network_manager`.
3. Добавь к нему Script component, укажи `network_manager.script` и задай ID компонента `network_manager`.
4. Пока карта и танки остаются как есть. Не удаляй `bot_spawner` на этом этапе.

В скрипте по умолчанию используется `ws://127.0.0.1:8080`, то есть сервер на этой же машине. Для подключения других компьютеров замени адрес на LAN IP или публичный адрес хоста; для внешнего доступа отдельно потребуется открыть порт и позже настроить TLS/WSS.

## 4. Проверка

1. Запусти сервер.
2. Запусти первый экземпляр игры — в логе должно появиться `Connected as player_1`.
3. Запусти второй экземпляр игры — он должен получить следующий ID, а первый экземпляр должен залогировать `Player joined`.
4. Закрой один клиент — оставшийся должен получить `Player left`.

Чтобы проверить синхронизацию координат вручную, другой скрипт может отправлять сообщения в компонент `main:/network_manager#network_manager`:

```lua
local position = go.get_position()
local _, _, body_angle = vmath.quat_to_euler(go.get_rotation())

msg.post("main:/network_manager#network_manager", "network_set_state", {
    x = position.x,
    y = position.y,
    body_angle = body_angle,
    turret_angle = 0
})
```

Для интеграции с реальными углами башни позже нужно передавать именно угол башни в той системе координат, которую использует текущий `turret_controller`. Этот фрагмент — тестовый вызов; пока он не добавлен в `tank_controller`, состояние танка не будет отправляться.

## Сообщения протокола на данный момент

- `welcome`: ID текущего клиента, индекс точки появления, список уже подключённых игроков.
- `player_joined` / `player_left`: присутствие игроков.
- `state`: координаты, угол корпуса и башни, передаваемые клиентом.
- `shot`: сетевое событие выстрела.
- `projectile_hit`: отчёт клиента о попадании.

## Важное ограничение

Это первая тестовая версия с пересылкой сообщений. Сервер назначает ID, отслеживает присутствие и проверяет базовый формат координат, но пока доверяет клиенту в вопросах движения, выстрелов и попаданий. Это соответствует выбранному прототипному подходу, но не защищает от читов. Также в этой стадии `network_manager` только кэширует состояния и пишет события в лог: создание/удаление удалённых танков и репликация урона подключаются следующим этапом.
